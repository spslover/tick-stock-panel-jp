## 2. 目标 SLI 定义

SLI 必须基于**已确认的口径、统计窗口与排除规则**才可成立。下表是建议口径, 其"排除规则"一列需在实现前由业务与 SRE 共同确认。

| SLI | 定义 | 统计窗口 | 排除规则 (待确认) | 目标 (设计目标) |
| --- | --- | --- | --- | --- |
| SLI-1 行情新鲜度 | `quote_age_ms` (最后一次成功轮询到现在) 的 P95 | 滚动 7 天 | 午休 11:30-13:00; 非交易日; 收盘后 15:35 起 | < 30s (交易时段) |
| SLI-2 行情成功率 | 成功轮次 / 总轮次 | 滚动 1 天 | 同上 | ≥ 99.5% |
| SLI-3 管道准时率 | 15:35 调度在 16:30 前完成的天数占比 | 滚动 30 个交易日 | 非交易日; 供应商侧故障需单列 | ≥ 98% |
| SLI-4 管道成功率 | 管道成功完成 / 触发次数 | 滚动 30 个交易日 | 非交易日 | ≥ 99% |
| SLI-5 数据完整性 | `integrity/scan` 报告为"无异常"的天数占比 | 滚动 30 个交易日 | 非交易日 | 100% (有异常即需修复闭环) |
| SLI-6 API 错误率 | 5xx / 总请求 | 滚动 1 天 | 客户端 4xx 不计入 | < 0.5% |
| SLI-7 API 时延 | 核心读接口 P95 | 滚动 7 天 | 重算类接口单列 | 由性能基线确定 (**当前无基线, 待建立**) |
| SLI-8 资源水位 | 进程 RSS / 容器限额; 数据目录磁盘占用 | 实时 | — | 内存 < 70%; 磁盘 < 80% |

> **可用性预算**: 若以 99.99% 为年可用性目标, 365 天下理论不可用预算约 **52.56 分钟**。
> 该数字**仅在** SLI 定义、统计窗口与排除规则被确认并实际采集满一个完整周期后才有意义。
> 代码修改、短时压测或一次演练**不能**证明全年达标。

## 4. 补偿控制 (在 `/metrics` + `/ready` 落地前)

| 缺口 | 补偿控制 | 频率 | 负责人 |
| --- | --- | --- | --- |
| 无机器可读指标 | 人工巡检: `GET /api/data/workload` + `GET /health` + 管道状态页 | 每交易时段 3 次 (09:35 / 11:30 / 14:45) | 值班人 |
| 无 readiness | 巡检时确认"管道状态页显示今日已完成"且"行情状态显示数据年龄 < 60s" | 同上 | 值班人 |
| 无告警投递 | 巡检发现异常即按 `runbook-core-links.md` 处理并记录 | 同上 | 值班人 |
| 无请求关联 ID | 排障时用时间戳 + 标的 + 线程名在 `backend.log` 中拼接 (并记录该局限) | 按需 | 值班人 |
| 无数据备份 | 定期复制 `data/` 到另一介质 (详见 `backup-restore-and-incident.md` §2) | 每日收盘后 | 值班人 |

> 补偿控制是**临时**措施, 不能作为 SLO 达标证据, 也不能替代 AL-09 这类安全告警。
